1 Por que ver os algoritmos antes da análise?

F1.2 vai te mostrar que busca binária custa O(log n) e Merge Sort custa O(n log n). Mas esses rótulos só fazem sentido se você já sabe o que esses algoritmos fazem. Sem isso, a análise é só manipulação de símbolos sem significado.

A diferença entre entender e decorar:

Decorar ✗
"Busca binária é O(log n) porque divide por 2."
— Você passa na questão de múltipla escolha, mas não sabe por quê divide por 2 nem o que "log n" tem a ver com isso.
Entender ✓
"Busca binária descarta metade a cada passo. Para n=1.000.000, são ~20 passos. Isso é log₂(n)."
— O número aparece naturalmente a partir do comportamento.

Neste módulo você vai ver os algoritmos funcionando — com animação, contagem de passos e comparação concreta. Não há notação O aqui. Os rótulos vêm em F1.2, depois que a intuição estiver formada.

→ Próximo passo (seção 2): começamos pelo mais simples — a busca linear. Você vai ver exatamente quantas comparações ela faz para diferentes tamanhos de lista, e por que isso é um problema quando a lista cresce.

2 Busca Linear

O problema: você tem uma lista de n números e quer saber se um valor alvo está nela — e se estiver, em qual posição.

A ideia: olhar para cada elemento, um por um, da esquerda para a direita. Se o elemento for o alvo, parou. Se acabar a lista sem achar, não está.

Animação — Busca Linear

Escolha um alvo e clique em Iniciar.
—

Contando os passos

Para uma lista de n elementos:

Melhor caso
1
Alvo é o 1º elemento
Caso médio
n/2
Alvo está no meio
Pior caso
n
Alvo não existe ou é o último

Na análise de algoritmos, quase sempre nos importamos com o pior caso — ele garante que o algoritmo nunca vai pior do que isso, independente dos dados.

O problema de escala: dobrar o tamanho da lista dobra o número de comparações no pior caso. Para n = 1.000.000, você pode fazer até 1 milhão de comparações só para descobrir que o elemento não está lá.
→ Próximo passo (seção 3): e se a lista estivesse ordenada? Poderíamos usar essa informação para buscar muito mais rápido — sem olhar para a maioria dos elementos.

3 Busca Binária

Pré-requisito: a lista precisa estar ordenada. Sem isso, o truque não funciona.

A ideia: em vez de olhar do início, olhe para o elemento do meio. Se o alvo for menor que o meio, ele só pode estar na metade esquerda — descarte a metade direita inteira. Repita no que sobrou.

Exemplo com 16 elementos, buscando 73:

1
Lista: [3, 7, 12, 18, 24, 31, 42, 55, 63, 73, 81, 88, 91, 95, 97, 99] → meio = posição 8 → valor 63
73 > 63 → descarta metade esquerda. Sobram 8 elementos.
2
[73, 81, 88, 91, 95, 97, 99] → meio = posição 4 → valor 91
73 < 91 → descarta metade direita. Sobram 4 elementos.
3
[73, 81, 88] → meio = posição 2 → valor 81
73 < 81 → descarta metade direita. Sobra 1 elemento.
4
[73] → meio = posição 1 → valor 73 = alvo ✓
Encontrado em 4 passos para uma lista de 16 elementos.
Padrão: 16 → 8 → 4 → 2 → 1. Isso é exatamente quantas vezes você divide 16 por 2 até chegar em 1: 4 vezes. Para n=1024 seriam 10 passos. Para n=1.000.000 seriam ~20 passos.

Escolha o tamanho da lista e o alvo, depois clique em Iniciar.

Custo oculto: busca binária exige que a lista esteja ordenada. Se você precisar ordenar antes de buscar, esse custo extra precisa ser considerado. Para uma única busca em lista desordenada, pode ser mais simples usar busca linear.
→ Próximo passo (seção 4): agora que você entende busca, vamos para ordenação — como colocar uma lista bagunçada em ordem. O primeiro algoritmo é o mais intuitivo, mas também o mais lento.

4 Bubble Sort

O problema: dado um array desordenado, colocá-lo em ordem crescente.

A ideia: compare pares de elementos adjacentes. Se estiverem na ordem errada, troque-os. Repita até não haver mais trocas. O nome vem do fato de que os elementos maiores "sobem" para o final como bolhas.

Trace: ordenar [5, 3, 8, 1, 4]

Passagem 1: [5,3,8,1,4] → troca(5,3) → [3,5,8,1,4] → ok(5,8) → troca(8,1) → [3,5,1,8,4] → troca(8,4) → [3,5,1,4,8] — o 8 chegou ao fim ✓
Passagem 2: [3,5,1,4,8] → ok(3,5) → troca(5,1) → [3,1,5,4,8] → troca(5,4) → [3,1,4,5,8] — o 5 chegou ao lugar ✓
Passagem 3: [3,1,4,5,8] → troca(3,1) → [1,3,4,5,8] — o 3 chegou ao lugar ✓
Passagem 4: [1,3,4,5,8] — nenhuma troca → ORDENADO ✓

Animação — Bubble Sort (passo a passo)

Clique em "Próximo passo" para avançar uma comparação por vez.
—

Por que fica lento?

Para ordenar n elementos, o Bubble Sort faz no máximo esta quantidade de comparações:

Passagem 1: n−1 comparações
Passagem 2: n−2 comparações
Passagem 3: n−3 comparações
...
Passagem n−1: 1 comparação

Total = (n−1) + (n−2) + ... + 1 = n(n−1)/2 ≈ n²/2 comparações

Para n=1000: cerca de 500.000 comparações. Para n=10.000: cerca de 50.000.000. Dobrar n quadruplica o trabalho — esse é o sinal de que algo cresce com n².

→ Próximo passo (seção 5): existe uma forma muito mais inteligente de ordenar. Em vez de comparar pares adjacentes, o Merge Sort usa uma estratégia chamada "dividir e conquistar" — e faz muito menos trabalho.

5 Merge Sort

A ideia central: dividir o problema em partes menores, resolver cada parte separadamente, depois juntar os resultados. Essa estratégia tem um nome: divisão e conquista.

O algoritmo em 3 linhas:

1. Dividir: corte o array ao meio. Agora você tem dois arrays menores.
2. Conquistar: aplique o mesmo algoritmo recursivamente em cada metade, até sobrar arrays de 1 elemento (que já estão "ordenados").
3. Combinar (Merge): junte duas metades ordenadas numa única lista ordenada — compare o primeiro de cada metade e escolha o menor, repetindo até esvaziar as duas.

Veja o trabalho por nível — árvore de chamadas

A chave para entender o custo do Merge Sort é visualizar quantas chamadas acontecem e quanto cada nível da árvore trabalha.

Construção da árvore de chamadas (n = 8)

A conta que explica o custo

Observe o padrão que a árvore revela:

Nível 01 lista de n elementos → merge custa n operações
Nível 12 listas de n/2 → cada merge custa n/2 → total n operações
Nível 24 listas de n/4 → cada merge custa n/4 → total n operações
...Cada nível sempre faz exatamente n operações no total
Quantos níveis existem? A cada nível dividimos por 2. Para n=8: 8→4→2→1 são 3 níveis (= log₂(8)).
Para n=1024: 10 níveis. Para n=1.000.000: ~20 níveis.

Custo total = n operações × log₂(n) níveis
Comparação concreta: para n = 1.000:
Bubble Sort: ~500.000 comparações
Merge Sort: ~10.000 comparações (50× menos)
Para n = 1.000.000: Bubble Sort faz ~500 bilhões de comparações. Merge Sort faz ~20 milhões. A diferença é de 25.000×.
📖 Continuação em F1.3: aqui você viu o Merge Sort de forma conceitual — a árvore de chamadas e a contagem de trabalho por nível. Em F1.3 (Recorrências) você vai voltar a esse mesmo algoritmo e aprender a derivar a mesma conta matematicamente, usando a equação T(n) = 2T(n/2) + n. O que você viu aqui vai fazer aquela equação ter sentido imediato.
→ Próximo passo (seção 6 — Quicksort): o Merge Sort sempre divide o array em duas metades exatamente iguais. E se a divisão não for igual? O Quicksort usa essa mesma ideia com uma variação que introduz um conceito novo: o custo depende do pivô escolhido.

6 Quicksort

O Quicksort é o algoritmo de ordenação mais usado na prática — Python, Java e C++ o usam internamente. Como o Merge Sort, é divisão e conquista. A diferença está em como divide.

A ideia: escolha um elemento como pivô. Reorganize o array para que todos os menores que o pivô fiquem à esquerda e os maiores à direita. Agora o pivô está na sua posição final definitiva. Repita para cada metade.

Trace: [5, 3, 8, 1, 4, 9, 2, 7] · pivô = 5 (primeiro elemento)

Array: [5, 3, 8, 1, 4, 9, 2, 7] pivô = 5
Menores: [3, 1, 4, 2] → [5] ← [8, 9, 7] :maiores
Recursão esq: ordenar [3, 1, 4, 2] → [1, 2, 3, 4]
Recursão dir: ordenar [8, 9, 7] → [7, 8, 9]
Resultado: [1, 2, 3, 4, 5, 7, 8, 9] ✓

Animação — Quicksort (particionamento passo a passo)

Clique "Próximo passo" para ver o particionamento. O pivô (laranja) vai para sua posição final.
—

O que muda quando o pivô é ruim

Observe o que acontece com a forma da árvore de chamadas dependendo do pivô:

✓ Pivô bom (divide ao meio)
n → n/2 e n/2 → árvore balanceada com log₂(n) níveis
Custo: n × log n (igual ao Merge Sort)
✗ Pivô ruim (divide em 0 e n−1)
n → 0 e n−1 → árvore degenerada com n níveis
Custo: n² (igual ao Bubble Sort)
Intuição-chave para F1.2: o Quicksort é o primeiro algoritmo onde pior caso e caso médio têm custos fundamentalmente diferentes. Em F1.2 você vai ver que O (pior caso) e Θ (comportamento típico) são notações distintas exatamente para capturar essa diferença.
Por que as linguagens usam Quicksort e não Merge Sort? Merge Sort precisa de memória extra para a etapa de mesclagem — O(n) espaço adicional. Quicksort ordena no próprio array. Na prática, com pivô escolhido como mediana de 3 elementos, o pior caso raramente ocorre.
→ Próximo passo (seção 7): agora que você viu todos os cinco algoritmos funcionando, vamos colocá-los lado a lado com os números reais — e ver por que a diferença de custo importa tanto quanto n cresce.

Três observações que vão fazer sentido em F1.2:

1
Busca Binária cresce quase imperceptivelmente. De n=100 para n=1.000.000 (fator 10.000×), os passos vão de 7 para 20. Adicionar zeros ao tamanho do problema adiciona passos contados. Em F1.2 isso se chama O(log n).
2
Busca Linear e tamanho do problema crescem juntos. 10× mais elementos → 10× mais comparações. Em F1.2 isso se chama O(n).
3
Merge Sort e Quicksort (caso médio) têm números quase idênticos. Ambos crescem como n×log n — a diferença é que o Quicksort usa menos memória e costuma ser mais rápido na prática pelas constantes ocultas.
4
Quicksort (pior caso) e Bubble Sort têm o mesmo custo. Um pivô péssimo transforma o Quicksort num algoritmo quadrático. Isso é o que F1.2 vai formalizar: O (pior caso) ≠ Θ (comportamento típico).
5
Bubble Sort explode. De n=1.000 para n=10.000 (fator 10×), as comparações vão de ~500 mil para ~50 milhões (fator 100×). Dobrar n quadruplica o trabalho. Em F1.2 isso se chama O(n²).
O que você vai fazer em F1.2: aprender a escrever formalmente "cresce como n²" ou "cresce como log n" usando a notação O, Ω e Θ. Mas o seu entendimento de o que está acontecendo você já tem — construído aqui, com números concretos.
