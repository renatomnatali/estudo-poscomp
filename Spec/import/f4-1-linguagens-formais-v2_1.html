Linguagens Formais e Autômatos

1 Conceitos Fundamentais

Quando você digita grep "erro.*crítico" log.txt no terminal, o sistema precisa verificar se cada linha do arquivo bate com o padrão — em milissegundos, em arquivos de gigabytes. Quando o compilador lê if (x > 0) { return x; }, ele precisa saber que aqueles símbolos formam código válido. Em ambos os casos, a ferramenta que viabiliza isso é um autômato guiado por uma gramática formal.

Linguagens formais são a teoria matemática por trás de qualquer sistema que processa texto com regras precisas: compiladores, bancos de dados, protocolos de rede, validadores de formulário, parsers de JSON. O POSCOMP testa se você entende por que certas linguagens são mais difíceis de reconhecer que outras, e qual mecanismo computacional é necessário para cada classe.

Alfabeto (Σ)

Conjunto finito e não-vazio de símbolos. Ex: Σ = {0, 1} para binário; Σ = {a, b, c, ..., z} para palavras.

String (palavra)

Sequência finita de símbolos de Σ. A string vazia é ε (epsilon). |w| é o comprimento de w. Ex: "010" tem |010|=3.

Linguagem (L)

Subconjunto de Σ*. Σ* = todas as strings sobre Σ incluindo ε. L pode ser finita ou infinita. Ex: L = {0ⁿ1ⁿ | n≥0}.

Concatenação

w·v = justaposição de w e v. "ab"·"cd"="abcd". Σ⁰={ε}, Σ¹=Σ, Σ² = {xy | x,y ∈ Σ}. Σ* = Σ⁰ ∪ Σ¹ ∪ Σ² ∪ ...

Formalismo de gramática: uma gramática G = (V, Σ, R, S) onde V = não-terminais, Σ = terminais, R = regras de produção, S ∈ V = símbolo inicial. O tipo das regras define a classe da linguagem.
→ Próximo passo (seção 2): agora que você sabe o que é uma linguagem formal, vamos ver como Chomsky as classificou em quatro classes aninhadas — cada uma reconhecível por um mecanismo computacional distinto.

2 Hierarquia de Chomsky

Por que um simples autômato finito consegue processar expressões regulares mas não consegue verificar se parênteses estão balanceados? Por que um compilador precisa de um mecanismo mais poderoso que um verificador de regex? A resposta está na hierarquia de Chomsky: linguagens mais complexas exigem máquinas com mais memória, e essa relação não é acidental — é matematicamente precisa.

Noam Chomsky classificou as linguagens em 4 tipos aninhados. Cada tipo mais externo contém o anterior, mas reconhecê-lo exige um autômato mais poderoso — e consequentemente mais lento. Clique em cada nível para explorar seus exemplos, limitações e aplicações.

Atenção (POSCOMP frequente): a hierarquia é estritamente aninhada — toda linguagem regular é LLC, toda LLC é sensível ao contexto, e por aí vai. Mas a recíproca não vale. Linguagens que exigem comparar duas quantidades arbitrariamente grandes não cabem em Tipo 3, porque autômatos finitos têm memória limitada — uma pilha é necessária (Tipo 2). Linguagens que exigem comparar três ou mais quantidades não cabem nem com pilha — sobem para Tipo 1. Saber em que ponto da hierarquia uma linguagem para é o que separa quem decora de quem entende.
→ Próximo passo (seção 3): a linguagem mais simples da hierarquia — o Tipo 3 — é reconhecida por Autômatos Finitos Determinísticos. Vamos entender o que é um AFD e o que ele pode (e não pode) fazer.

3 Autômato Finito Determinístico (AFD)

Imagine um sistema com um número fixo de "modos de operação" — como um semáforo com estados VERDE, AMARELO, VERMELHO. Ele lê um símbolo de cada vez da entrada, e com base no estado atual e no símbolo lido, muda para exatamente um novo estado. Sem memória além do estado atual. Sem pilha, sem fita, sem nada além disso. Esse é o Autômato Finito Determinístico.

Essa extrema simplicidade é também sua limitação: um AFD não consegue "contar" arbitrariamente — não pode garantir que leu tantos 'a's quanto 'b's, porque para isso precisaria de memória ilimitada. Mas para padrões sem contagem — "string que contém 'ab'", "string de comprimento par", "email válido" — o AFD é rápido, eficiente e suficiente.

Formalmente, um AFD é uma quíntupla M = (Q, Σ, δ, q₀, F) onde Q = estados, Σ = alfabeto, δ: Q×Σ→Q = função de transição total e determinística, q₀ ∈ Q = estado inicial, F ⊆ Q = estados de aceitação. Para cada estado e símbolo, existe exatamente uma transição.

AFD mínimo: para cada linguagem regular existe um AFD com o menor número possível de estados — o AFD mínimo. O algoritmo de minimização identifica e une estados equivalentes (estados que para qualquer string futura têm o mesmo comportamento).
→ Próximo passo (seção 4): o AFD exige uma transição para cada símbolo em cada estado — isso pode tornar sua construção trabalhosa. O AFN relaxa essa restrição, tornando a construção mais natural. Mas isso tem um custo: o não-determinismo precisa ser resolvido na hora da conversão.

4 Autômato Finito Não-Determinístico (AFN)

Construir um AFD diretamente para uma linguagem como "strings que terminam em 'ab'" é possível, mas trabalhoso: você precisa rastrear os últimos dois símbolos lidos em todo momento. Um AFN resolve isso de forma mais natural: o autômato simplesmente adivinha quando encontra o padrão e toma o caminho certo.

Na prática, "adivinhar" significa que o AFN pode, diante de um símbolo, ramificar para múltiplos estados ao mesmo tempo — ou até mudar de estado sem consumir símbolo algum (transição-ε). A string é aceita se existe ao menos um caminho que termina em estado de aceitação.

Formalmente, no AFN a função de transição é δ: Q×(Σ∪{ε}) → 𝒫(Q) — ela mapeia para um conjunto de estados, não para um único estado.

Teorema de Rabin-Scott: para todo AFN existe um AFD equivalente que reconhece a mesma linguagem. A construção de subconjuntos (subset construction) converte um AFN de n estados em um AFD com até 2ⁿ estados. Na prática, a explosão raramente ocorre, mas no pior caso é inevitável.

→ Próximo passo (seção 5): AFDs e AFNs são mecanismos. Expressões regulares são a linguagem para descrever esses mesmos padrões de forma compacta. O Teorema de Kleene garante que as três notações — AFD, AFN, ER — descrevem exatamente a mesma classe de linguagens.

5 Expressões Regulares (ER)

Expressões regulares descrevem exatamente as linguagens regulares (Tipo 3). Operações base: concatenação (AB = "A seguido de B"), alternância (A|B = "A ou B"), fechamento de Kleene (A* = "zero ou mais A's"), além de A⁺ (um ou mais) e A? (zero ou um).

Teorema de Kleene: uma linguagem é regular ⟺ pode ser descrita por uma expressão regular ⟺ existe um AFD que a reconhece. As três representações são equivalentes e há algoritmos para converter entre elas (Thompson's construction ER→AFN, Berry-Sethi AFN→ER).

→ Próximo passo (seção 6): expressões regulares e AFDs cobrem o Tipo 3. Para ir além — para parênteses balanceados, expressões aritméticas, a sintaxe de uma linguagem de programação — precisamos do Tipo 2: Gramáticas Livres de Contexto.

6 Gramáticas Livres de Contexto (GLC)

Um compilador precisa verificar se if (x > 0) { while (y != 0) { y--; } } é código válido. Expressões regulares não conseguem fazer isso: elas não reconhecem estruturas aninhadas arbitrariamente, como blocos dentro de blocos. O motivo é simples — um AFD não tem memória para rastrear a profundidade do aninhamento.

Gramáticas Livres de Contexto resolvem isso exatamente. Elas descrevem estruturas recursivas: "uma expressão é uma soma de termos, um termo é um produto de fatores, um fator pode ser uma expressão entre parênteses." Essa auto-referência captura o aninhamento ilimitado que os AFDs não conseguem.

Formalmente, uma GLC G = (V, Σ, P, S) gera linguagens Tipo 2. Regras de produção têm a forma A → α onde A ∈ V e α ∈ (V ∪ Σ)*. O adjetivo "livre de contexto" vem do fato de A poder ser expandido independentemente do contexto em que aparece.

Subestrutura recursiva: GLC podem expressar estruturas aninhadas como parênteses balanceados, expressões aritméticas, e a maioria das sintaxes de linguagens de programação — exatamente o que os compiladores precisam.

Exemplo: gramática para expressões aritméticas simples

E → E + T | E − T | T
T → T * F | T / F | F

Gramática Ambígua: uma GLC é ambígua se a mesma string admite duas árvores de derivação diferentes. Exemplo clássico: E → E+E | E*E | num é ambígua porque "2+3*4" pode ser parseada como (2+3)*4 ou 2+(3*4). Compiladores exigem gramáticas não-ambíguas (ou regras de precedência externas).

Forma Normal de Chomsky (FNC)

Toda GLC pode ser convertida em FNC onde todas as produções têm a forma A → BC ou A → a. Isso é importante para provas e para o algoritmo CYK de parsing em O(n³).

→ Próximo passo (seção 7): a GLC gera linguagens Tipo 2. Para reconhecer essas linguagens — processar o código de entrada e verificar se é válido — precisamos de um mecanismo com memória: o Autômato com Pilha.

7 Autômato com Pilha (AP)

O que impede um AFD de verificar se "{aⁿbⁿ | n ≥ 0}" é a falta de memória: ele não consegue lembrar quantos 'a's leu. A solução é simples na ideia: acrescente uma pilha ao AFD. A cada 'a' lido, empilhe. A cada 'b' lido, desempilhe. Se a pilha ficar exatamente vazia no fim da string, os números batem — aceita.

Esse mecanismo adicional — uma pilha infinita — transforma um AFD em um Autômato com Pilha, e essa transição de poder computacional é exatamente o que separa o Tipo 3 do Tipo 2 na hierarquia de Chomsky.

Formalmente, um AP = (Q, Σ, Γ, δ, q₀, Z₀, F). Γ é o alfabeto da pilha, Z₀ é o símbolo inicial da pilha. A transição δ: Q×(Σ∪{ε})×Γ → 𝒫(Q×Γ*) lê um símbolo, desempilha o topo e empilha uma nova string. APs reconhecem exatamente as linguagens livres de contexto.

Simulador AP: reconhece {aⁿbⁿ | n≥1}

Estratégia: empilha um símbolo 'A' por cada 'a' lido; desempilha um por cada 'b'. Pilha vazia ao final → aceita.

AP não-determinístico vs determinístico: diferente dos AFDs, APs não-determinísticos (APND) são estritamente mais poderosos que APs determinísticos (APD). Existe linguagem LLC que não é reconhecida por nenhum APD. Isso difere dos AFDs/AFNs que têm o mesmo poder.
→ Próximo passo (seção 8): você já sabe que {aⁿbⁿ} é LLC e não regular. Mas como provar matematicamente que nenhum AFD possível reconhece essa linguagem? Para isso existe o Pumping Lemma — a principal ferramenta para demonstrar que uma linguagem não pertence a uma classe.

8 Pumping Lemma

O Pumping Lemma é a principal ferramenta para provar que uma linguagem NÃO é regular (ou NÃO é LLC). É uma prova por contradição: assumimos que a linguagem é regular, aplicamos o lema, chegamos em contradição → portanto não é regular.

Pumping Lemma para Linguagens Regulares

Se L é regular, então existe p ≥ 1 (comprimento de bombeamento) tal que toda string w ∈ L com |w| ≥ p pode ser escrita como w = xyz onde:

xprefixo
y|y| ≥ 1, bombeável
zsufixo
com as condições: (1) |y| ≥ 1, (2) |xy| ≤ p, (3) para todo i ≥ 0, xyⁱz ∈ L ("bombear" y qualquer número de vezes mantém a string na linguagem).

Pumping Lemma para LLC: similar mas mais forte. Se L é LLC, existe p tal que w ∈ L com |w| ≥ p pode ser escrita como w = uvxyz com |vy| ≥ 1, |vxy| ≤ p, e para todo i ≥ 0, uvⁱxyⁱz ∈ L. Usado para provar que {aⁿbⁿcⁿ} não é LLC.
→ Próximo passo (seção 9): teoria na bagagem — hora de ver onde tudo isso vive no mundo real. Compiladores, regex, HTML parsers, protocolos de rede: cada um usa exatamente o nível da hierarquia que o problema exige.

9 Aplicações

A hierarquia de Chomsky não é um exercício acadêmico — ela descreve precisamente quanto poder computacional cada problema exige. Entender isso explica por que um grep em arquivo de 10 GB termina em segundos (AFD: O(n) no tamanho do texto) enquanto um parser de XML é mais complexo (AP: Tipo 2), e por que certas validações que parecem simples na verdade não são regulares.

🔍

Grep / Regex

Tipo 3 — AFD

grep, sed, awk, re do Python — todos compilam expressões regulares para AFDs. Busca em O(n) no tamanho do texto.

⚙️

Compiladores

Tipo 2 — GLC / AP

Análise léxica (tokens) usa AFDs. Análise sintática (parser) usa GLC — LL(1), LR(1), LALR. GCC, Clang, javac.

🌐

HTML / XML Parser

Tipo 2 — GLC

HTML e XML são LLCs (tags aninhadas). Browsers usam parsers baseados em GLC para construir a DOM. HTML5 é Tipo 2 estendido.

🔒

Protocolos

Tipo 3 — AFD

TCP, HTTP, Bluetooth implementam máquinas de estado (AFDs) para gerenciar conexões: CLOSED → SYN_SENT → ESTABLISHED → etc.

🧠

NLP / LLMs

Tipo 2+ — GLC probabilísticas

Gramáticas probabilísticas livres de contexto (PCFGs) são base de parsers de linguagem natural. Modelos como GPT usam atenção para capturar dependências além do Tipo 2.

📋

Validação de formulários

Tipo 3 — ER / AFD

Validação de email, CPF, CEP, telefone, cartão de crédito — todas são linguagens regulares, implementadas com regex em milissegundos.

11 Resumo

🎯 O que você precisa dominar

Hierarquia de Chomsky: Tipo 3 (Regular/AFD) ⊂ Tipo 2 (LLC/AP) ⊂ Tipo 1 (SC/ALD) ⊂ Tipo 0 (RE/MT). Cada nível é reconhecido por um mecanismo mais poderoso.
AFD = (Q, Σ, δ, q₀, F). δ total e determinística. AFN = δ pode ir para múltiplos estados ou ε. Todo AFN tem AFD equivalente (até 2ⁿ estados via subset construction).
Teorema de Kleene: Regular ⟺ ER ⟺ AFD. As três representações são equivalentes. ER usa concatenação, alternância (|) e Kleene star (*).
GLC = A → α (um não-terminal à esquerda). Gera linguagens Tipo 2. Compiladores usam GLC para sintaxe. Gramática ambígua = mesma string tem duas árvores. FNC: A → BC | a (usada para CYK em O(n³)).
AP = AFD + pilha infinita. APND reconhece todas as LLC. APD é estritamente menos poderoso que APND (ao contrário de AFD vs AFN).
Pumping Lemma: prova que L NÃO é regular por contradição. Não pode provar que É regular. Análogo existe para LLC. {aⁿbⁿ} é LLC (não regular). {aⁿbⁿcⁿ} é SC (não LLC).
